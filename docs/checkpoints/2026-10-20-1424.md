## Decisions
- devtools только для разработки: флаг, а не API; каждое подключение подтверждает диалог с «Deny» по умолчанию (закрытие окна = отказ), e2e-сборки всегда отказывают и печатают токен; на Windows без манифеста common controls v6 rfd не передаёт подписи кнопок, поэтому там отказ всегда (безопасная деградация); токен Servo даёт рабочую аутентификацию только при 8 знаках (жёсткий префикс 25), e2e перезапускает запуск с другим токеном вместо слепого повтора.
- os-power: один процессный наблюдатель на `OnceCell` с повтором при отмене/ошибке, источники по ОС (Windows power callback, macOS NSWorkspace, Linux logind через zbus 5.19.0 с теми же фичами, что уже в дереве: в Cargo.lock меняется только список зависимостей alef-modules); `idle` не делал (записано в docs).
- log: лимит 200 записей/с на процесс, размерные пределы между процессами через файловую блокировку; паника пишет отчёт синхронно до предыдущего hook; сбой рендерера Servo не подключён (у делегата нет папки отчётов).
- Правка CI для docs-only: шаг типов пропускается, пакеты glib ставятся на каждом прогоне без docs-only; на проверку ждёт docs-only прогон (прогон слияния devtools-spike был отменён более новым пушем).
- Агенты rush завершили по два-три прохода с FAIL: devtools-impl и тесты os-power доделал сам, остальные три (os-power, http, log) вели rush с точными списками правок после ревью.

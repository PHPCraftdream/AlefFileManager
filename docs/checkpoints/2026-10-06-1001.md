## Decisions

- M1.4a и M1.4b реализую сам в worktree, а не через rush-агента: «умный» агент делегирует работу помощникам, те падают на длинных промптах (обрезка, пустые ошибки), и агент сдаётся; повторные «continue» не помогали — отвергнуто: бесконечные перезапуски агента.
- `transport` лежит в `alef_core::protocol::transport`, а не в `alef_core::transport`: иначе в `alef-core/src` было бы 8 записей при лимите 7.
- Рукопожатие: bootstrap-токен на runtime (как прежний capability в фрагменте URL) + допустимый `Origin` → `runtime.hello` отдаёт токен текущей сессии окна; все остальные вызовы — с токеном сессии, привязанным к окну; любой отказ — один и тот же 403 — отвергнуто: токен без привязки к окну и разные тексты отказов.
- Servo-канал тела: если `done_chan` установлен, fetch читает тело ТОЛЬКО из него (`wait_for_response`), поэтому все ответы транспорта идут через канал чанками ≤256 KiB с гарантированным терминалом (`Done`/`Cancelled`) — отвергнуто: `ResponseBody::Done` для маленьких ответов.
- `native://invoke` и доставка событий через `evaluate_javascript` остаются до M1.6 (File Manager не ломается между шагами); spike-маршруты — до M1.7; голые имена команд File Manager на новом пути живут как `app.<имя>`.

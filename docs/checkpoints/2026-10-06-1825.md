## Decisions

- Поставка как у Java: runtime отдельно (несколько версий рядом, лаунчер выбирает по `runtime` в манифесте), приложение — zip `.alef` с подписью ed25519, `alef run` и `alef install` (ярлык/AUMID, `.app`-обёртка, `.desktop`), единая сборка — опция; MCP — JS-пакет поверх модулей — отвергнуто: одна глобальная версия runtime, Rust-крейт `rmcp` внутри runtime.
- Права: пользователь подтверждает и может подменить (не отказать) любое право, приложение не должно отличить подмену; `cli` — заранее объявленные фиксированные команды; ядро согласия отдельным этапом M2b перед `fs` — отвергнуто: делать подмену отдельно в каждом модуле потом.
- `window.create` разрешается необязательным `permissions.window.create` в манифесте (универсальный `alef` не имеет Rust-хоста, чтобы включить право); `setSize` рантайм сам держит в min/max (Windows не применяет лимиты к программному ресайзу); заголовок окна хранит рантайм (winit не читает его на X11) — отвергнуто: право только для встраивающего хоста.
- Тихие e2e: `ALEF_E2E_QUIET=1` (окна не показываются, видимость/фокус/maximize виртуальные, геометрия и события настоящие), `assertQuiet` в раннере, `startup` только с `ALEF_E2E_VISIBLE=1` — отвергнуто: отдельный рабочий стол Windows (WGL `MakeCurrentFailed`), позиционирование окон за экраном (Windows возвращает их в рабочую область при показе).
- Не запускать e2e без успешной сборки: цепочки команд только через `&&`; никаких e2e из деревьев без тихого режима.

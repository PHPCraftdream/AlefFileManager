# M0.5 — Безоконный режим Servo: результаты

Вопрос и среды — `../m0-spikes.md`, раздел «M0.5». Код спайка одноразовый: `alef-runtime/src/spikes/headless.rs` (включается `ALEF_SPIKE_HEADLESS=1`), страница и раннер — `experiments/headless/` (`node experiments/headless/run.mjs [--raf] [--throttle] [--windowed] [--hold-ms N]`).

## Как устроено

Процесс без цикла событий winit создаёт `SoftwareRenderingContext` 1×1, `Servo` (с нашим реестром протоколов и будильником на `Condvar`), скрытый `WebView` на тот же `native://app` и сам крутит `spin_event_loop`: после прохода ждёт будильник не дольше `ALEF_SPIKE_IDLE_MS` (250 мс по умолчанию). Запросы к окну (`window.*`, диалоги) получают отказ: окна нет. Страница делает `app.info`, `fetch`, таймеры и пишет в stdout (`ALEF_E2E HEADLESS ...`); по `app.quit` процесс завершается с этим кодом.

Что понадобилось, чего не видно заранее:

- Webview нужно привязать к идентификатору окна в реестре транспорта (`bridge.windows()`): иначе `runtime.hello` документа получает `PERMISSION_DENIED`. В режиме без окна идентификатор выделяет сам runtime.
- `Host::quit` не будит цикл: он смотрит на запрос выхода не реже, чем раз в 250 мс. В M4 нужен общий будильник, который `quit` и запросы приложения умеют будить.
- Делегат должен печатать сообщения консоли страницы, иначе падение страницы не видно вообще.

## Windows, обычный сеанс (отладочная сборка)

| Что | Результат |
|---|---|
| `SoftwareRenderingContext` 1×1 | создаётся, 130–200 мс от старта процесса (адаптер WGL «software» годится) |
| Скрытый `WebView` | +25 мс |
| Старт процесса → первый `app.info` страницы | 250–375 мс (окно с тихим режимом: 2,4–4,0 с — окно, контекст WGL, ожидание первого кадра) |
| JS страницы | работает: таймеры (111 тиков за 12 с при 100 мс), `fetch` к `native://`, транспорт (`app.info`, `e2e.echo`), `window.*` отвечает `CLOSED` |
| Память, частный объём процесса | 77 МиБ против 241 МиБ у окна в тихом режиме; пик рабочего набора 137 против 167 МиБ (рабочий набор в простое ОС обрезает до 6–10 МиБ — по нему судить нельзя) |
| CPU в простое, страница без анимации | 0,4 % одного ядра (около 4 пробуждений в секунду) |
| CPU в простое, страница держит `requestAnimationFrame` | 1,1–1,8 % одного ядра: около 27 кадров в секунду |
| `webview.hide()` и `set_throttled(true)` | `requestAnimationFrame` не останавливают; refresh driver скрытого `WebView` идёт |
| Окон у процесса | нет (`MainWindowHandle` 0) |
| Завершение | `app.quit(0)` — код 0 в пределах 250 мс |

Вывод для Windows в обычном сеансе: безоконный режим работает на программном контексте `surfman` без запасного пути; режим «консоль» обещать можно. Приложение без анимации почти ничего не стоит в простое; приложение с постоянной анимацией держит 1–2 % ядра даже скрытым.

## Раннеры GitHub Actions (отладочная сборка, шаг «Headless spike (no window)»)

| Среда | Результат |
|---|---|
| Linux x64, без `DISPLAY` (EGL surfaceless, Mesa) | работает: контекст 56 мс, `WebView` 72 мс, первый `app.info` через 203 мс; частный объём 219 МиБ; CPU в простое около 0 %; процесс без окна, выход с кодом 0. Под `xvfb` то же: 178 мс, 218 МиБ |
| macOS arm64 (раннер, сеанс с графикой) | работает: контекст 218 мс, `WebView` 486 мс, первый `app.info` через 824 мс; 97 МиБ; 0,2 % ядра; окна нет |
| macOS x64 (раннер) | работает: 428 / 537 / 901 мс; 71 МиБ; 0,5 % ядра; окна нет |
| **Windows x64 (раннер, без графического драйвера)** | **не работает**: `software context: RequiredExtensionUnavailable`, процесс завершается с кодом 1. `SoftwareRenderingContext` на `surfman` (WGL) требует расширений OpenGL, которых нет у базового драйвера без GPU: на машине разработчика с драйвером видеокарты тот же код работает (см. выше) |

Вывод: на Linux и macOS безоконный режим на программном контексте подтверждён. Для Windows он зависит от драйвера OpenGL: на раннере без видеокарты (так же будет на сервере и, вероятно, в службе) режим «консоль» без запасного пути работать не будет. Запасные пути, которые надо проверить до обещания в M4: контекст через ANGLE (EGL поверх D3D11/WARP, `surfman` умеет, но сборка без ANGLE у нас сейчас), либо скрытое окно 1×1 с тем же программным путем, что у обычного окна.

## Не проверено

| Среда | Статус |
|---|---|
| Windows-служба (session 0) | не проверено. Попытка воспроизвести отдельным рабочим столом (`CreateDesktop`) в этой среде вернула 87 (неверный параметр) — это ошибка приёма, а не результат; нужна настоящая служба или планировщик под SYSTEM |
| macOS без сеанса `WindowServer` (SSH, демон) | не проверено: раннер GitHub дает графический сеанс; нужна ручная проверка |
| Windows с графическим драйвером, но в сеансе службы | не проверено (см. строку про службу) |

Открыто: безоконный режим на Windows без графического драйвера (см. таблицу раннеров): запасной путь нужен до того, как M4 пообещает режим «консоль» на Windows; формулировки M4 и M7 об этом стоит уточнить.

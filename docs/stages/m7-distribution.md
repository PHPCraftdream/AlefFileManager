# M7 — Дистрибуция

Обзор: `../FRAMEWORK-PLAN.md` §6.3. Зависит от M3 (генерический бинарник `alef`, File Manager как JS-приложение), M2b (согласие и подмена прав) и CI из M0.4.

## Цель

Поставка как у Java: **runtime ставится отдельно, приложение — пакет `.alef`**; единая сборка (runtime в установщике приложения) — необязательная опция. Разработчик без Rust: `npm create alef-tron` → `npm run dev` → `npm run build` даёт пакет `.alef`; `npm run bundle` — по желанию установщик с runtime внутри. Этап делится на три части.

| Часть | Что |
|---|---|
| M7a | runtime и лаунчер: установщики runtime, версии рядом, `alef run`, ассоциация `.alef`, самообновление runtime |
| M7b | пакеты: формат `.alef`, подпись, `@alef-tron/tools`, `alef install`, идентичность приложения, обновление пакета (`updater`) |
| M7c | единая сборка (опция): runtime и пакет в одном установщике |

## M7a — runtime и лаунчер

- **Установка runtime** — установщик (Windows: MSI/NSIS, macOS: `.pkg`/`.dmg`, Linux: AppImage/`.deb`) и npm-пакеты для разработки: `@alef-tron/runtime-win32-x64`, `-darwin-arm64`, `-darwin-x64`, `-linux-x64` (бинарник `alef`, `os`/`cpu` в `package.json`) и мета-пакет `@alef-tron/runtime` (выбор бинарника при запуске, как esbuild).
- **Версии рядом:** `<корень Alef>/<версия>/alef`; в системе один лаунчер `alef`, который читает `runtime: ^X.Y` из манифеста пакета и запускает подходящую установленную версию. Подходящей нет — понятная ошибка с командой установки (`alef runtime install <версия>`); неиспользуемые версии убирает `alef runtime prune`.
- **Запуск:** `alef run <пакет.alef|каталог> -- <аргументы>`; двойной клик по `.alef` (ассоциация типа файла) делает то же. Каталог остаётся для разработки (`dev`).
- **Самообновление runtime:** новая версия ставится рядом со старыми и не ломает установленные приложения; подпись обновления проверяется (ed25519, ключ проекта).
- **Размер:** release-бинарник runtime ~118 МБ (Windows, Servo 0.6): теперь это размер одной установки, а не каждого приложения. Цели: strip символов, LTO в релизе, сжатие в установщике; замер на каждой платформе в CI.

## M7b — пакеты и установка приложений

### Пакет `.alef`

zip: `alef.ktav` в корне, ассеты, `icon.png`, `META-INF/` — список хешей всех файлов и подпись ed25519 разработчика. Ассеты читаются из архива без распаковки на диск (источник ассетов моста — каталог или архив). Подпись проверяется до запуска; неподписанный пакет запускается с предупреждением (политика пользователя). Манифест задаёт `runtime: ^X.Y` — требуемый диапазон версий runtime.

#### Формат 1 (общий договор читателя на Rust и упаковщика на JS)

Оба конца пишутся по этому тексту независимо; расхождение находит перекрёстная проверка на общих файлах-векторах (пакет, собранный JS, читает Rust, и наоборот; сломанные пакеты отвергают оба). Формат узкий намеренно: всё, что два разбора ZIP могли бы понять по-разному, запрещено, а не уточнено.

**Контейнер.** Файл — ровно: записи подряд (local header, затем данные), без промежутков; затем central directory; затем EOCD из 22 байт с комментарием нулевой длины. Ни префикса, ни суффикса, ни промежутков, ни пересечений, ни второго архива; EOCD — последние 22 байта файла, все смещения отсчитываются от начала файла и проверяются с контролем переполнения. Порядок записей в central directory совпадает с порядком local headers. Запрещены: ZIP64, data descriptors, дополнительные поля (extra length равна 0 в обоих заголовках), комментарии записей, шифрование, многотомность, записи-каталоги и любые записи кроме обычных файлов (внешние атрибуты читатель игнорирует и никогда не использует как тип или права). Общие флаги записи равны ровно `0x0800` (UTF-8, бит 11). Методы сжатия 0 (stored) и 8 (deflate); CRC-32 записан и в local header, и в central directory и проверяется; имя (побайтно), метод, флаги, CRC-32 и оба размера в local header и в central directory совпадают. Единственный источник перечня записей — central directory, и все потребители пакета (лаунчер, runtime, updater, установщик) читают файлы только через один проверенный источник; чтение соседних файлов на диске и второй независимый разбор ZIP запрещены.

**Пределы.** Проверяются по объявленным значениям до выделения памяти и распаковки: файл архива не больше 2304 МиБ, central directory не больше 16 МиБ, записей не больше 10 000, файл не больше 512 МиБ несжатым, сумма несжатых размеров не больше 2 ГиБ, `META-INF/hashes` не больше 16 МиБ, `META-INF/signature` не больше 256 байт. Объявленному размеру не доверяется: распаковка обязана потребить ровно compressed size байт и выдать ровно uncompressed size байт (для stored они равны), чтение останавливается на объявленном размере + 1 байт и это ошибка.

**Имена.** Только ASCII, и только байты `A–Z a–z 0–9 . _ - @ +` и разделитель `/`. Всё остальное — отказ (пробел, не-ASCII, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`, `%`, `~`, управляющие символы). Так два разбора не могут разойтись из-за кодировок, нормализации Unicode, регистра за пределами ASCII и псевдонимов Windows; расширение алфавита — задача следующей версии формата, не уточнение этой. Имя не пусто и не начинается с `/`; сегменты не пусты, не равны `.` и `..`, не заканчиваются точкой, не длиннее 255 байт; имя целиком не длиннее 1024 байт; часть сегмента до первой точки не равна (без учёта регистра) `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`. Два имени, равные после приведения ASCII-букв к нижнему регистру, — дубликаты (отказ); имя файла не может быть началом пути (по сегментам) другой записи. Зарезервированные имена `alef.ktav`, `META-INF/hashes`, `META-INF/signature` имеют только это точное написание: запись, равная зарезервированному без учёта регистра, но отличающаяся побайтно, — ошибка; под `META-INF/` (в любом регистре) других записей нет.

**Состав.** Обязателен файл `alef.ktav` в корне. Остальное — файлы пакета (в том числе необязательный `icon.png`); подпись покрывает все они, а какие из них видны странице, решает манифест, не формат.

**`META-INF/hashes`.** UTF-8 без BOM, строки заканчиваются `\n` (последняя тоже), не больше 10 000 строк. Строка: 64 hex-символа нижнего регистра SHA-256 содержимого файла, два пробела, имя записи (как в архиве). Строки по возрастанию имён, сравнение лексикографическое по беззнаковым байтам (для ASCII это код символа; при совпадении начала короткое имя идёт первым; сортировка по умолчанию `.sort()` в JS, использующая UTF-16, допустима только потому, что имена ASCII). Каждый файл архива кроме `META-INF/*` ровно в одной строке, лишних строк нет, пустых строк, `\r` и BOM нет.

**`META-INF/signature`.** UTF-8, ровно три строки с `\n` в конце: `alef-package 1`, `key <base64>` (32 байта открытого ключа Ed25519), `sig <base64>` (64 байта подписи). Base64 по RFC 4648 §4: без пробелов и переносов, с обязательным `=`, с нулевыми неиспользуемыми битами; признак — повторное кодирование декодированных байт даёт исходную строку побайтно. Подписывается сообщение `alef-package-v1\n` + точные байты `META-INF/hashes`. Нормативна проверка в runtime (Rust): Ed25519 по RFC 8032 с отказом при S ≥ L и при A или R малого порядка (`verify_strict`); проверка в @alef-tron/tools — удобство разработчика, её «подпись верна» не означает, что runtime примет пакет, а пакеты, которые собирает сам упаковщик, проходят обе. Отпечаток ключа — SHA-256 открытого ключа, hex нижнего регистра; это идентичность ключа, а не подтверждённое имя разработчика: интерфейс показывает отпечаток и состояние доверия к нему, и не выдаёт имя из манифеста за удостоверенную личность подписанта.

**Проверка при открытии.** (1) контейнер, пределы, имена и состав; (2) есть `signature` — есть и `hashes`, подпись верна; (3) есть `hashes` — набор файлов равен набору списка, хеш каждого файла совпадает (полный проход, до запуска); (4) каждое чтение файла проверяет его хеш по списку ещё раз. Нет `signature` — пакет **не подписан**: результат «не подписан», но если `hashes` есть, он проверяется так же. Любое расхождение — ошибка, а не предупреждение. Результат открытия: `Signed { key, fingerprint }` или `Unsigned`. Таблица записей, список хешей, ключ и результат подписи фиксируются при открытии и на весь сеанс; повторное открытие архива по пути их не заменяет. Чтение возвращает потребителю только полностью проверенные байты: до совпадения CRC-32 и SHA-256 никакие куски не передаются, не выполняются и не разбираются, а проверка и потребление работают над одним и тем же снимком байт в памяти (не над повторным чтением файла и не над изменяемым отображением в память).

**Упаковщик.** Записи расположены по возрастанию имён (то же сравнение), local headers и central directory в одном порядке. Поля фиксированы: версия «создано» `0x031E` (Unix, 3.0), версия «нужно» 20, флаги `0x0800`, время DOS 0 и дата DOS `0x0021` (1980-01-01), внешние атрибуты `0x81A40000` (обычный файл 0644), без дополнительных полей и комментариев. Метод 8 для файла, который он делает меньше, иначе 0; байты deflate зависят от сборки zlib, поэтому тот же вход даёт те же байты на одной версии Node, а подпись покрывает хеши содержимого, не байты архива. Закрытый ключ — только у разработчика (`alef-tron keys`), в пакет не попадает.

**Требования к установке и обновлению** (не часть читателя; обязательны для M7a и остального M7b).

- Устанавливаемый пакет имеет в проверенном `alef.ktav` `id` и `version` (SemVer 2.0.0); регистрационные данные, диапазон `runtime` и ассоциации берутся только из проверенного манифеста, вложенные архивы — обычные файлы и не распаковываются.
- При установке сохраняются проверенные `id` и 32 байта ключа подписи, а также наибольшая принятая версия. Updater сравнивает кандидата с этой записью, а не с ключом из доставленного пакета или повторно открытого прежнего файла; `updater.publicKey`, если задан, обязан совпадать с ключом установленного пакета.
- Обновление допускается только при точном совпадении `id`, том же ключе и версии, большей сохранённой наибольшей (по SemVer, без build metadata); откат — только отдельным явным действием пользователя. Имя приложения не заменяет `id`.
- Для ранее подписанного установленного приложения отсутствие подписи — ошибка; запуск такого пакета как неподписанного требует отдельного явного решения пользователя и не наследует доверие, права и идентичность прежней установки.
- Команда запуска, которую строит установщик, — путь и массив аргументов без оболочки; значения манифеста в `.desktop`, XML, plist и скриптах кодируются по правилам формата, а не подставляются как текст команды: подпись не очищает строки.

### Установка

`alef install <пакет.alef>` (или согласие при первом запуске) копирует пакет в каталог приложений пользователя и создаёт **идентичность приложения**, хотя бинарник общий:

- Windows: ярлык с AppUserModelID (имя и значок в панели задач, уведомления приложения);
- macOS: тонкая обёртка `.app` (`Info.plist`: id, имя, значок, описания TCC), которая запускает `alef run`;
- Linux: `.desktop` с `MimeType` для deep links.

Ассоциации файлов, deep links и автозапуск регистрируются как `alef run <пакет> ...`. `alef uninstall <id>` убирает всё созданное. Решения по правам (M2b) хранятся отдельно и удаляются по желанию.

### Пакеты npm и команды `@alef-tron/tools`

| Пакет | Содержимое |
|---|---|
| `@alef-tron/api` | JS API (`packages/api`), сборка ESM + `.d.ts` |
| `@alef-tron/mcp` | MCP-сервер и клиент (M4b) |
| `@alef-tron/tools` | CLI `alef-tron`: `dev`, `build`, `pack`, `bundle`, `check`, `keys`; зависит от `@ktav-lang/ktav` для проверки `alef.ktav` |
| `create-alef-tron` | шаблон: `alef.ktav` (разделы безопасности закрыты), Vite/Rsbuild на выбор, пример вызова API, пример обработки подмены прав (таймауты сети, пустая ФС) |

Организацию `alef-tron` в npm зарегистрировать до первой публикации.

- `dev` — проверить `alef.ktav`, запустить dev-сервер фронтенда (команда из `package.json` или конфига) и `alef run . --dev-url http://127.0.0.1:<port>`; HMR; закрытие окна останавливает dev-сервер.
- `build` — проверить манифест, собрать фронтенд, сложить `dist/` + `alef.ktav` в каталог приложения.
- `pack` — собрать и подписать пакет `.alef` из каталога приложения (`keys` создаёт и хранит ключ разработчика).
- `check` — проверка манифеста и окружения.

### `updater`

```ts
updater.check(): Promise<{ available: boolean, version?, notes? }>
updater.download({ onProgress? }): Promise<void>
updater.install(): Promise<never>    // перезапуск
```

- Манифест: `updater: { endpoint: https://..., publicKey: <ed25519> }`; обновляется **пакет** `.alef` (подпись ключом разработчика проверяется до установки; ключ должен совпасть с прежним, иначе — отказ и новый вопрос о доверии). Новые права в обновлении спрашиваются заново (M2b).
- Обновление требуемой версии runtime: если пакет требует более новый runtime, updater сообщает и предлагает поставить его.

## M7c — единая сборка (опция)

`alef-tron bundle` кладёт runtime рядом с пакетом и собирает обычный установщик: Windows — NSIS или MSI (WiX), подпись signtool; macOS — `.app` (Info.plist, TCC), `.dmg`, codesign + нотаризация; Linux — AppImage и `.deb`. Приложение ставится одним файлом и не зависит от общего runtime. Ассеты — пакет `.alef` рядом с бинарником (позже — внутри ресурса бинарника).

## CI и выпуск

- Матрица из M0.4; релизный workflow по тегу: сборка runtime на 4 конфигурациях → артефакты → установщики runtime и публикация npm-пакетов `@alef-tron/runtime-*`, затем `@alef-tron/runtime`, `@alef-tron/api`, `@alef-tron/mcp`, `@alef-tron/tools`, `create-alef-tron` с согласованной версией.
- Версия протокола транспорта и версия `@alef-tron/api` проверяются рукопожатием `runtime.hello`; диапазон `runtime` из манифеста проверяет лаунчер.
- Политика версий: semver; до 1.0 — minor может ломать API, фиксируется в CHANGELOG; поэтому несколько версий runtime стоят рядом.

## Приёмка

| Проверка | Как |
|---|---|
| Чистая машина без Rust: `npm create alef-tron`, `dev`, `build`, `pack`, `alef run` пакета | CI-job на трёх ОС |
| Лаунчер выбирает версию по `runtime` манифеста; при отсутствии — понятная ошибка | e2e |
| Подпись: пакет с изменённым файлом не запускается; чужой ключ при обновлении — отказ | e2e |
| `alef install` создаёт ярлык/обёртку/`.desktop` с идентичностью приложения, `uninstall` убирает | ручная на трёх ОС |
| Установщик runtime ставит, запускает, удаляет; версии рядом не мешают друг другу | ручная на трёх ОС |
| File Manager собран как обычное Alef-приложение (пакет `.alef`) и установлен | ручная |
| `updater`: обновление с подписью ставится; с неверной подписью — отказ | e2e |
| Единая сборка (M7c): установщик со встроенным runtime работает на чистой машине | ручная |
| npm-пакеты публикуются из CI по тегу | dry-run публикации |

## Риски

- Идентичность приложения без своего бинарника: на macOS нужна `.app`-обёртка на каждое приложение, её подпись и нотаризация — открытый вопрос; без них — предупреждение Gatekeeper. На Windows AUMID задаётся только через ярлык (при запуске на месте уведомления общие).
- Подпись и нотаризация macOS требуют Apple Developer аккаунта; без них — неподписанные сборки с предупреждением Gatekeeper.
- Несколько версий runtime рядом — место на диске и поддержка старых версий (политика: исправления безопасности только для последней minor до 1.0).
- Время сборки Servo в CI — кэш обязателен; релизная сборка на 4 платформах — часы.

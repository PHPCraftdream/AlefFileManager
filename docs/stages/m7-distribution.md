# M7 — Дистрибуция

Обзор: `../FRAMEWORK-PLAN.md` §6.3. Зависит от M3 (генерический бинарник `alef`, File Manager как JS-приложение), M2b (согласие и подмена прав) и CI из M0.4.

## Цель

Поставка как у Java: **runtime ставится отдельно, приложение — пакет `.alef`**; единая сборка (runtime в установщике приложения) — необязательная опция. Разработчик без Rust: `npm create alef-tron` → `npm run dev` → `npm run build` даёт пакет `.alef`; `npm run bundle` — по желанию установщик с runtime внутри. Этап делится на три части.

| Часть | Что |
|---|---|
| M7a | runtime и лаунчер: установщики runtime, версии рядом, `alef run`, ассоциация `.alef`, самообновление runtime |
| M7b | пакеты: формат `.alef`, подпись, `@alef-tron/tools`, `alef install`, идентичность приложения, обновление пакета (`updater`) |
| M7c | единая сборка (опция): runtime и пакет в одном установщике |

## M7a — runtime и лаунчер

- **Установка runtime** — установщик (Windows: MSI/NSIS, macOS: `.pkg`/`.dmg`, Linux: AppImage/`.deb`) и npm-пакеты для разработки: `@alef-tron/runtime-win32-x64`, `-darwin-arm64`, `-darwin-x64`, `-linux-x64` (бинарник `alef`, `os`/`cpu` в `package.json`) и мета-пакет `@alef-tron/runtime` (выбор бинарника при запуске, как esbuild).
- **Версии рядом:** `<корень Alef>/<версия>/alef`; в системе один лаунчер `alef`, который читает `runtime: ^X.Y` из манифеста пакета и запускает подходящую установленную версию. Подходящей нет — понятная ошибка с командой установки (`alef runtime install <версия>`); неиспользуемые версии убирает `alef runtime prune`.
- **Запуск:** `alef run <пакет.alef|каталог> -- <аргументы>`; двойной клик по `.alef` (ассоциация типа файла) делает то же. Каталог остаётся для разработки (`dev`).
- **Самообновление runtime:** новая версия ставится рядом со старыми и не ломает установленные приложения; подпись обновления проверяется (ed25519, ключ проекта).
- **Размер:** release-бинарник runtime ~118 МБ (Windows, Servo 0.6): теперь это размер одной установки, а не каждого приложения. Цели: strip символов, LTO в релизе, сжатие в установщике; замер на каждой платформе в CI.

## M7b — пакеты и установка приложений

### Пакет `.alef`

zip: `alef.ktav` в корне, ассеты, `icon.png`, `META-INF/` — список хешей всех файлов и подпись ed25519 разработчика. Ассеты читаются из архива без распаковки на диск (источник ассетов моста — каталог или архив). Подпись проверяется до запуска; неподписанный пакет запускается с предупреждением (политика пользователя). Манифест задаёт `runtime: ^X.Y` — требуемый диапазон версий runtime.

#### Формат 1 (общий договор читателя на Rust и упаковщика на JS)

Оба конца пишутся по этому тексту независимо; расхождение находит перекрёстная проверка (пакет, собранный JS, читает Rust, и наоборот).

**Архив.** ZIP; методы сжатия 0 (stored) и 8 (deflate); без шифрования, без многотомности, ZIP64 не нужен (записей < 65535, размер < 4 ГиБ). Пределы читателя: записей не больше 10 000, файл не больше 512 МиБ несжатым, всего не больше 2 ГиБ; объявленный размер не доверяется — чтение останавливается на объявленном размере + 1 байт и это ошибка. Записи-каталоги (имя на `/`) допустимы и игнорируются.

**Имена.** UTF-8, разделитель `/`. Отказ при: пустом имени, начале с `/`, `\`, `:`, NUL и управляющих символах, сегментах `.`, `..` и пустых, сегменте с пробелом или точкой в конце, сегменте — имени устройства Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, с расширением или без, без учёта регистра), имени длиннее 255 байт в сегменте или 1024 байт целиком, двух записях с одним именем (сравнение без учёта регистра).

**Состав.** Обязателен файл `alef.ktav` в корне. Под `META-INF/` допустимы только `META-INF/hashes` и `META-INF/signature`. Остальное — ассеты (в том числе необязательный `icon.png`).

**`META-INF/hashes`.** UTF-8 без BOM, строки заканчиваются `\n` (последняя тоже). Строка: 64 hex-символа нижнего регистра SHA-256 содержимого файла, два пробела, имя записи (как в архиве). Строки по возрастанию байтов UTF-8 имени. Каждый файл архива кроме `META-INF/*` ровно в одной строке, лишних строк нет.

**`META-INF/signature`.** UTF-8, ровно три строки с `\n` в конце: `alef-package 1`, `key <base64>` (32 байта открытого ключа Ed25519), `sig <base64>` (64 байта подписи); base64 стандартный, с `=`. Подписывается сообщение `alef-package-v1\n` + точные байты `META-INF/hashes` (чистый Ed25519, RFC 8032; читатель принимает только канонические подписи — `verify_strict`). Отпечаток ключа — SHA-256 открытого ключа, hex нижнего регистра; это идентичность разработчика (его показывают пользователю, с ним сравнивает `updater`).

**Проверка при открытии.** (1) имена, пределы и состав; (2) есть `signature` — есть и `hashes`, подпись верна; (3) есть `hashes` — набор файлов равен набору списка, хеш каждого файла совпадает (полный проход, до запуска); (4) каждое последующее чтение файла проверяет его хеш по списку ещё раз (архив на диске мог измениться после открытия). Нет `signature` — пакет **не подписан**: результат «не подписан», но если `hashes` есть, он проверяется так же. Любое расхождение — ошибка, а не предупреждение. Результат открытия: `Signed { key, fingerprint }` или `Unsigned`.

**Упаковщик.** Архив детерминирован: записи по имени, метки времени 1980-01-01 00:00:00, внешние атрибуты `0o100644`, без дополнительных полей и комментария; тот же вход даёт те же байты. Закрытый ключ — только у разработчика (`alef-tron keys`), в пакет не попадает.

### Установка

`alef install <пакет.alef>` (или согласие при первом запуске) копирует пакет в каталог приложений пользователя и создаёт **идентичность приложения**, хотя бинарник общий:

- Windows: ярлык с AppUserModelID (имя и значок в панели задач, уведомления приложения);
- macOS: тонкая обёртка `.app` (`Info.plist`: id, имя, значок, описания TCC), которая запускает `alef run`;
- Linux: `.desktop` с `MimeType` для deep links.

Ассоциации файлов, deep links и автозапуск регистрируются как `alef run <пакет> ...`. `alef uninstall <id>` убирает всё созданное. Решения по правам (M2b) хранятся отдельно и удаляются по желанию.

### Пакеты npm и команды `@alef-tron/tools`

| Пакет | Содержимое |
|---|---|
| `@alef-tron/api` | JS API (`packages/api`), сборка ESM + `.d.ts` |
| `@alef-tron/mcp` | MCP-сервер и клиент (M4b) |
| `@alef-tron/tools` | CLI `alef-tron`: `dev`, `build`, `pack`, `bundle`, `check`, `keys`; зависит от `@ktav-lang/ktav` для проверки `alef.ktav` |
| `create-alef-tron` | шаблон: `alef.ktav` (разделы безопасности закрыты), Vite/Rsbuild на выбор, пример вызова API, пример обработки подмены прав (таймауты сети, пустая ФС) |

Организацию `alef-tron` в npm зарегистрировать до первой публикации.

- `dev` — проверить `alef.ktav`, запустить dev-сервер фронтенда (команда из `package.json` или конфига) и `alef run . --dev-url http://127.0.0.1:<port>`; HMR; закрытие окна останавливает dev-сервер.
- `build` — проверить манифест, собрать фронтенд, сложить `dist/` + `alef.ktav` в каталог приложения.
- `pack` — собрать и подписать пакет `.alef` из каталога приложения (`keys` создаёт и хранит ключ разработчика).
- `check` — проверка манифеста и окружения.

### `updater`

```ts
updater.check(): Promise<{ available: boolean, version?, notes? }>
updater.download({ onProgress? }): Promise<void>
updater.install(): Promise<never>    // перезапуск
```

- Манифест: `updater: { endpoint: https://..., publicKey: <ed25519> }`; обновляется **пакет** `.alef` (подпись ключом разработчика проверяется до установки; ключ должен совпасть с прежним, иначе — отказ и новый вопрос о доверии). Новые права в обновлении спрашиваются заново (M2b).
- Обновление требуемой версии runtime: если пакет требует более новый runtime, updater сообщает и предлагает поставить его.

## M7c — единая сборка (опция)

`alef-tron bundle` кладёт runtime рядом с пакетом и собирает обычный установщик: Windows — NSIS или MSI (WiX), подпись signtool; macOS — `.app` (Info.plist, TCC), `.dmg`, codesign + нотаризация; Linux — AppImage и `.deb`. Приложение ставится одним файлом и не зависит от общего runtime. Ассеты — пакет `.alef` рядом с бинарником (позже — внутри ресурса бинарника).

## CI и выпуск

- Матрица из M0.4; релизный workflow по тегу: сборка runtime на 4 конфигурациях → артефакты → установщики runtime и публикация npm-пакетов `@alef-tron/runtime-*`, затем `@alef-tron/runtime`, `@alef-tron/api`, `@alef-tron/mcp`, `@alef-tron/tools`, `create-alef-tron` с согласованной версией.
- Версия протокола транспорта и версия `@alef-tron/api` проверяются рукопожатием `runtime.hello`; диапазон `runtime` из манифеста проверяет лаунчер.
- Политика версий: semver; до 1.0 — minor может ломать API, фиксируется в CHANGELOG; поэтому несколько версий runtime стоят рядом.

## Приёмка

| Проверка | Как |
|---|---|
| Чистая машина без Rust: `npm create alef-tron`, `dev`, `build`, `pack`, `alef run` пакета | CI-job на трёх ОС |
| Лаунчер выбирает версию по `runtime` манифеста; при отсутствии — понятная ошибка | e2e |
| Подпись: пакет с изменённым файлом не запускается; чужой ключ при обновлении — отказ | e2e |
| `alef install` создаёт ярлык/обёртку/`.desktop` с идентичностью приложения, `uninstall` убирает | ручная на трёх ОС |
| Установщик runtime ставит, запускает, удаляет; версии рядом не мешают друг другу | ручная на трёх ОС |
| File Manager собран как обычное Alef-приложение (пакет `.alef`) и установлен | ручная |
| `updater`: обновление с подписью ставится; с неверной подписью — отказ | e2e |
| Единая сборка (M7c): установщик со встроенным runtime работает на чистой машине | ручная |
| npm-пакеты публикуются из CI по тегу | dry-run публикации |

## Риски

- Идентичность приложения без своего бинарника: на macOS нужна `.app`-обёртка на каждое приложение, её подпись и нотаризация — открытый вопрос; без них — предупреждение Gatekeeper. На Windows AUMID задаётся только через ярлык (при запуске на месте уведомления общие).
- Подпись и нотаризация macOS требуют Apple Developer аккаунта; без них — неподписанные сборки с предупреждением Gatekeeper.
- Несколько версий runtime рядом — место на диске и поддержка старых версий (политика: исправления безопасности только для последней minor до 1.0).
- Время сборки Servo в CI — кэш обязателен; релизная сборка на 4 платформах — часы.

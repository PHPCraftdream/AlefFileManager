# M9 — безопасный мост приложения к AI-ролям Rush

> **Статус: контракт + реализация заглушки (M9.2, задача #164).** Контракт ниже реализован в объёме M9.2 — см. раздел 9: манифестная секция `permissions.ai`, команды `ai.roles`/`ai.chat`/`ai.tools.*`, сегмент `@alef-runtime/api/ai` и e2e-сценарий, за трейтом `AiProvider` с заглушечными бэкендами (обычная сборка — `MissingProvider`, e2e — детерминированный `FakeProvider`); реальный транспорт Rush — задача #167. Требования **TARGET**, не упомянутые в разделе 9, остаются нереализованными. Наблюдения основаны на статическом чтении кода.

## 1. Назначение и границы

M9 задаёт асинхронный мост Alef к ограниченным ролям Rush, установленного и настроенного пользователем. Это не клиент HTTP провайдера и не передача приложению ключей. Rush хранит и использует credentials и выбирает provider/model по своей конфигурации. Документ, JS, зависимости, ответы модели и обработчики инструментов приложения недоверенные; декларация манифеста лишь ограничивает запрос, сама полномочий не выдаёт.

```text
документ приложения → @alef-runtime/api (TARGET)
 → authority/manifest/consent (TARGET) → исполнитель AI Alef (TARGET)
 → интерфейс Rush (TARGET, транспорт не выбран) → конфигурация Rush пользователя
```

Публичного Alef API, исполнителя AI, адаптера Rush и журнала M9 пока нет. У Rush есть публичный Go SDK (`sdk/sdk.go:1-42`, `:70-93`: `Open`/`Run`, `Client`, алиасы запросов/результатов/учётных данных/ролей). Это встраиваемый Go API, не IPC и не готовая граница безопасности: встраивание ключей в Alef нарушит инвариант Rush-only; транспорт не выбран. Готовый scoped IPC-адаптер Alef ↔ Rush в исследованных исходниках не найдено. У Rush существуют Web API и SDK; ни один из них не является готовым адаптером M9.

- Alef: `../APP-RUNTIME.md`, `../FRAMEWORK-PLAN.md`, `../stages/m2b-consent.md`, `../stages/m3-data.md`, `../stages/m4-net-cli.md`, `../stages/m7-distribution.md` (M7a.1); ревью `../reviews/2026-10-09-full-review.md`.

В `run.go` закреплены ровно четыре слота; дополнительных произвольных ролей не предполагается. `reviewer` — дополнительный проход, не финальный ответ исполнителя. `--json` даёт итоговый JSON, `--stream` — поток текста, это разные режимы. Встроенные инструменты Rush нельзя автоматически передавать Alef. Накопленная стоимость и снимки токенов не обеспечивают точного предварительного списания будущих шагов.

Rush настраивает ключи через конфигурацию и resolver; гарантия «только keyring» — **не найдено**. M4 CLI запускает процессы без OS sandbox и наследует окружение (`../stages/m4-net-cli.md`); `.rush.json`/`rush.json` и окружение доступны однопользовательскому процессу с соответствующими правами. M3 namespace secrets не является хранилищем ключей Rush и не защищает от сырого CLI. Гарантия полноты очистки всех ошибок — **не найдено**.

## 2. Проектный API Alef

Каждая операция асинхронна; ниже проектный TypeScript-псевдоконтракт, не существующий код. Все методы имеют конечные дедлайны из §6.

```ts
export interface Role {
  id: string;
  title: string;
  description: string;
  capabilities: ('text' | 'tool_calls' | 'usage' | 'cancel')[];
}
export type ChatMessage =
  | { role: 'user'; content: string }
  | { role: 'assistant'; content: string };
export type ChatPart =
  | { type: 'text'; text: string }
  | { type: 'tool_call'; id: string; name: string; arguments: unknown }
  | { type: 'usage'; inputTokens?: number; outputTokens?: number;
      cacheReadTokens?: number; cacheCreationTokens?: number;
      estimated: boolean; complete: boolean }
  | { type: 'end'; reason: 'completed' };
export interface ChatOptions {
  role: string;
  messages: ChatMessage[];
  tools?: string[];
  signal?: AbortSignal;
}
export interface AiTools {
  handle(name: string, handler: (args: unknown, context: {
    callId: string; signal: AbortSignal;
  }) => Promise<unknown>): Promise<() => Promise<void>>;
}
export interface AiApi {
  roles(): Promise<Role[]>;
  chat(options: ChatOptions): AsyncIterable<ChatPart>;
  tools: AiTools;
}
```

`text` означает только текстовые части, `tool_calls` — наблюдение вызовов инструментов, `usage` — доступность учёта, `cancel` — возможность запросить отмену. Перечень ролей scoped по authority, ограничен длиной и дедлайном 10 с; не раскрывает конфигурацию Rush или существование запрещённых ролей. Роль без обязательных для запроса возможностей недоступна.

Сообщения `user` и `assistant` допустимы. Запрещены сообщения `system`, `tool`, произвольные метаданные провайдера, скрытые рассуждения и чужая история. История assistant, придуманная приложением, и результат его инструмента — недоверенные данные, а не доказательство ответа модели. API не принимает session ID, provider/model, endpoint, headers, ключи, транспортный токен или пользовательскую схему.

Параметр `tools` по умолчанию пуст; в него можно включить лишь объявленные и разрешённые имена. До `chat` должен быть зарегистрирован обработчик. Дублирование регистрации даёт `BUSY`; отсутствующий обработчик — `INVALID_ARGUMENT` до старта. Регистрация подменённого инструмента возвращает инертный unregister; регистрация запрещённого инструмента отклоняется с `PERMISSION_DENIED`. Подмена роли возвращает `NOT_AVAILABLE` и не отправляет данные провайдеру. Отказ возвращает `PERMISSION_DENIED`. Имена не расширяют право. Существующие вызовы app tools остаются на исходных полномочиях приложения: запрос модели не может их расширить.

Runtime проверяет форму событий, размер, конечность/неотрицательность usage и идентификаторы. Выход break/return из AsyncIterable закрывает чат и вызывает отмену; никто не исполняет инструмент повторно по ChatPart.tool_call. Вызов инструмента диспетчеризуется независимо от чтения async iterator. `context.signal` срабатывает при закрытии чата, выгрузке документа и timeout. Исключение обработчика становится очищенной tool error. Результат ограничивается размером и общей проверкой JSON-формы; отдельная схема результата здесь не объявлена. Привязка одноразового внутреннего состояния: authority, сессия документа, чат, call ID, версия/хеш схемы, состояние ожидания. `callId` — только корреляция, не полномочие. Повтор, устаревший, чужой или отменённый результат отвергается. Async unregister идемпотентен; после его возврата новые вызовы не начинаются, runtime инвалидирует ожидающие, но не отменяет уже случившиеся побочные эффекты.

Usage в Rush — снимки, не приращения. Публичный Alef API MUST NOT копировать последний Rush snapshot как накопительный chat usage и MUST NOT суммировать последовательные снимки. Публичный usage определён как накопительные токены по всему чату и всем попыткам inference; cache-read и cache-creation — раздельные категории, не складываемые повторно с input/output. Rush snapshots переводятся через ledger usage сообщений/попыток, не сложением snapshot’ов. `estimated` явно отражает оценку, `complete:false` — отсутствующие данные; при неполноте/оценке не заявлять точность. Поле стоимости отсутствует: оно не определено. Для жёсткой token quota без доступной верхней границы или обязательства до попытки — fail closed, попытку не начинать. `tool_call` не раскрывает сырые кадры провайдера. Успех имеет ровно одно завершение `end(completed)`; cancel и ошибки завершаются `CLOSED`/`AlefError`, включая cancel, без `end(cancelled)`. Ошибки до открытия потока или при `next()` отклоняют операцию; после end событий нет. На каждую операцию ровно один исход. Закрытие/отписка инвалидирует результат и ограничивает ожидание runtime, но не может безопасно отменить уже выполняемые побочные эффекты JS.

## 3. Манифест, полномочия и согласие

Добавляется закрытый по умолчанию `permissions.ai`. Пример Ktav-подобной структуры (без запятых):

```text
permissions: {
    ai: {
        roles: [smart]
        tools: [
            {
                name: summarizeSelection
                description: Summarize selected text
                schema: {
                    type: object
                    properties: { text: { type: string } }
                    required: [text]
                    additionalProperties: false
                }
            }
        ]
    }
}
```

Схемы ограничены конкретным простым подмножеством JSON Schema: object, string, number, integer, boolean, null, array; `properties`, `required`, `items`, `enum`, числовые/строковые/массивные пределы, `additionalProperties: false`. Обязательны конечные ограничения: глубина максимум 32, properties максимум 256 на объект, массив имеет объявленный конечный максимум. Запрещены внешние `$ref`, неизвестные ключи и неограниченные глубина, размер и число свойств. Имена — ASCII строка 1–64 символа по regex `[a-zA-Z][a-zA-Z0-9_]{0,63}`. Дубли имён — ошибка. Значения и результаты ограничены сериализованным размером.

Каждая роль и каждый инструмент — отдельные права и отдельное согласие; каждая роль и каждый инструмент помечаются рискованными и требуют отдельного дополнительного подтверждения. Точные escaped scope ID: `ai.role:smart` и `ai.tool:summarizeSelection`. Манифест не выдаёт права и не задаёт решение пользователя. Схема и описание показываются в доверенном интерфейсе с экранированием. Изменение схемы, описания или смысла требует нового согласия. Каждый отмеченный как high risk scope требует отдельного дополнительного подтверждения по M2b. Идентичность — authority runtime M7a.1, не публичный ID, строка приложения или один токен документа.

| Риск, требующий отдельного доверенного согласия | Механизм и исходы |
|---|---|
| Каждая роль AI: отправка выбранных сообщений/данных и возможная стоимость | Полный перечень роли и возможностей; разрешить, подменить или отказать. Подмена — `NOT_AVAILABLE`, без отправки; отказ — `PERMISSION_DENIED`. |
| Каждый инструмент приложения: возможные побочные эффекты | Показывать имя, описание и каноническую схему; разрешить, подменить (исключить из набора, регистрация инертна) или отказать (регистрация отклоняется). |

Любой инструмент приложения — рискованный эффект; согласие не делает его честным. До запуска инструмента обязательны доверенное уведомление и запись в журнале. Это доверенный UI/CLI Alef, не UI приложения; в headless режиме допустима только реально доступная пользователю запись журнала. Если доверенное уведомление/журнал недоступны, инструмент не запускается. В журнале — authority, app ID, роль, инструмент, время, исход; секреты, заголовки и сырые ошибки исключены. Полные запросы/ответы не сохраняются по умолчанию. Предлагаемый `alef ai log <app-id>` доступен пользователю, не JS; неоднозначная идентичность отклоняется.

Согласия выполняются только пользовательским механизмом M2b, не API приложения. Действия страницы и обработчика не могут подтвердить право. Подмена роли не публикуется в доступных ролях и не отправляет запрос; подмена инструмента исключает его, отказ запрещает. Не раскрывать существование запрещённых глобальных имён.

## 4. Угроза и границы защиты

Угрозы: недоверенные страницы и зависимости, prompt injection, злонамеренный обработчик, поддельные/повторные ответы, процесс sidecar/CLI того же пользователя, утечка окружения/файлов/ошибок/заголовков, обход напрямую к провайдеру, эксфильтрация через сеть, межприложенческие журналы и квоты, DoS и незапрошенные/повторные вызовы инструментов. Prompt injection типами не устраняется.

| Атака/актив | Обязательный механизм / честная граница |
|---|---|
| Файлы, окружение и секреты Rush | Запретить несовместимые сырой CLI/sidecar/shell и доступ к файлам/окружению Rush без проверенной OS-изоляции или отдельного принципала. Защищённый runtime_home не ограничивает внешний процесс того же пользователя. |
| Ошибки и provider headers | Rush-only credentials; все ошибки должны быть очищены, но гарантия для всех путей — **не найдено**; до доказательства нельзя обещать полноту. |
| Прямой provider/net | Нет ключей Rush, endpoint или маршрутизирующих параметров в API. Прямой запрос с собственными credentials приложения не запрещён сам по себе, если отдельно выдано сетевое право. |
| Redirect/маршрут/чужой app | Runtime не позволяет приложению перенаправить собственный AI provider path и не передаёт ему ответ ДРУГОГО приложения. Приложение вправе эксфильтровать собственные данные в рамках прав net/external; native и page network контролируются независимо. AI право не даёт net, files или CLI права. |
| Другие приложения, журналы и квоты | Authority связывает подписанный app ID с fingerprint подписи, а неподписанный app ID — с digest неизменяемого архива; не каждый новый digest подписанной версии создаёт новую identity. Журнал и квота изолированы на authority приложения. |
| Tool injection, replay, поддельная история | Только объявленные/согласованные инструменты, доверенная запись перед запуском, одноразовая привязка; app-created assistant history и собственные tool results остаются недоверенными. |
| Спам, повторы, незапрошенные вызовы | Ограниченные очереди, кредиты, дедлайны и квоты на попытки; принимать только вызовы текущего Rush turn и зарегистрированного инструмента. |

Защищаемые активы: ключи провайдера, запросы и ответы ДРУГИХ приложений, невыданные роли Rush, журнал и квота чужой authority, корреляция вызовов инструментов. Целевой инвариант: ключи остаются только в Rush; ни страница, ни процесс Alef не получают их. Приложение может переслать собственный законно полученный ответ по отдельно выданному сетевому праву; гарантия не является запретом такого использования.

Жёсткое условие выпуска: до OS-изоляции запрещать запуск недоверенного приложения, если несовместимый сырой CLI/sidecar/shell либо общий доступ к Rush config/data/env позволяет украсть секреты. Это касается приложений и без `permissions.ai`. Уже работающие неограниченные sibling-процессы того же пользователя также препятствуют гарантии. M3 namespace `secrets` не защищает от raw CLI. Не считать предупреждение, denylist или согласие заменой OS-границы. Скомпрометированная ОС и сознательная передача пользователем секрета вне границы — вне модели.

Каждый чат — новая ограниченная сессия Rush: без личной истории, workspace/cwd приложения, контекстного поиска, встроенных bash/fs/net/MCP/hooks, reviewer/subagent и автономного делегирования. Если отключение полномочия не подтверждено, отказать в запуске. Существующий Web API Rush (TCP `/auth`, `/auth/check`, `/ws`, широкие session/config/log-команды) не является адаптером Alef; пользовательская аутентификация не изолирует процессы одного пользователя. Go SDK не служит IPC. Наблюдаемая SQLite persistence/workspace ownership не являются полномочиями или app authority.

## 5. Исполнение и будущий интерфейс Rush

BUS только валидирует ограниченный конверт/сессию и ставит в очередь. Асинхронный actor согласия, исполнитель AI и адаптер выполняют медленный ввод-вывод вне BUS. Порядок: проверка источника и размера → ограниченное неблокирующее принятие (`BUSY`) → согласие → атомарная квота → scoped session → stream с credit/cancel → доверенный журнал → ограниченный обработчик → одноразовый результат → учёт → проверка сессии и завершение. Целевой тип — именно `alef_core::session::executor::BlockingExecutor`: bounded submit, без ожидания результата на BUS; это будущая зависимость из BUS-договора, отсутствующая в checkout. Разрешение держится до фактического окончания работы.

Выгрузка/навигация инвалидирует сессию документа: прекращает новый допуск. Сужение/отзыв прав применяется перед dispatch и перед пересылкой результата: затронутые чаты отменяются; расширение действует со следующего запуска. Она не отзывает стабильную authority пакета и не убивает другие окна. Authority hash/correlation ID не bearer и не секрет; транспортный session token, если есть, остаётся защищённым authentication secret. Подтверждение control, отмена, close и end используют отдельный резерв бюджета вызовов, не исчерпываемый обычными данными. Credit выдаётся до запуска производителя. Непотребляемый поток может исчерпать bounded credit и завершиться по дедлайну; легитимный потребитель также обязан читать своевременно.

Будущий псевдоинтерфейс, не реализация и не выбор транспорта; все операции async и имеют конечные дедлайны:

```text
trait RushAiProvider {
  async authenticate_peer(runtime_identity, protocol_version) -> Result<Capabilities>
  async open_scoped_session(allowed_roles, tool_definitions_and_schemas,
                            restrictions, quota_commitment) -> Result<Session>
  async list_available_roles(session, scoped_authority) -> Result<BoundedRoleList>
  async stream(session, role, messages, limits) -> Result<CreditStream<TypedEvent>>
  async grant_credit(handle: OpaqueHandle, bytes) -> Result<()>
  async send_tool_result(session, single_use_binding, bounded_json) -> Result<()>
  async cancel(session, reason) -> Result<()>
  async close(session) -> Result<()>
}
```

`stream` возвращает credit-controlled stream; consumer явно вызывает async `grant_credit(handle, bytes)`. Close/cancel независимы от data budget. Handles opaque, bounded lifetime, не page-visible. Конечные дедлайны есть у каждой операции, включая role listing (10 с). Интерфейс обязан обеспечить взаимную аутентификацию, ограниченные роли и определения/схемы инструментов (не только имена), обязательства лимитов, типизированные события, bounded credit, отмену и очищенные ошибки. Отказать при невозможности доказать аутентичность или ограничения. TCP/HTTP/WebSocket/CLI пока не выбраны; широкий Web API нельзя выдавать приложению. Будущий транспорт — отдельная задача #167, указана также в §8.

## 6. Пределы, квоты и ошибки

Все числа ниже — **предлагаемые конечные TARGET**, пользователь может уменьшить их; это не текущие свойства runtime и не произвольные бесконечные настройки.

| Предел | Предложение |
|---|---:|
| Регистрация инструмента | 10 с |
| Ожидание согласия | 120 с |
| Подключение к адаптеру | 10 с |
| Перечень ролей | 10 с |
| До первого события | 30 с |
| Простой потока | 60 с |
| Чат целиком, включая обработчики | 300 с; каждый обработчик не более 30 с |
| Дренирование после отмены | 5 с; поздний результат подавляется, ёмкость удерживается до реального завершения |
| Ожидающие запросы | приложение 8, всего 64 |
| Параллельные чаты | приложение 2, всего 16 |
| Входное сообщение целиком | 256 KiB, включая накладные расходы схемы |
| Инструменты на приложение | 32 |
| Схема/аргументы/результат инструмента | не более 64 KiB сериализованных данных каждый |
| Кредит потока / размер части | 1 MiB / 256 KiB |

Действует самый ранний общий или этапный дедлайн. Отмена запрещает позднюю публикацию, но не утверждает безопасную отмену побочных эффектов JS. Все очереди и буферы ограничены; насыщение даёт `BUSY`/`TIMEOUT`, не бесконечное накопление.

Пользователь задаёт лимит запросов и токенов в сутки отдельно для каждой authority приложения, общий для всех окон и процессов этого приложения; дополнительно возможен общий лимит пользователя. Сутки определяются часовым поясом пользователя. Запись квоты атомарна; при переводе часов назад сутки/лимит не выдаются повторно, переход границы фиксируется по устойчивой отметке времени и одному календарному ключу. Пересечение чатом границы суток делится по фактическим попыткам: каждая попытка относится ко дню её старта; следующий шаг после смены дня требует резерва нового дня. «Запрос» — каждая фактическая попытка inference, включая retry/round, не вызов списка ролей. Резерв перед каждой попыткой атомарен для authority; необязательная роль не обходит общий лимит. Токены резервируются по известной верхней границе/обязательству; если его нет — fail closed, попытку не начинать. Неизвестность не возвращает резерв автоматически. Если перед очередным tool round лимит исчерпан — остановка с `QUOTA_EXCEEDED`, без тихого продолжения. Rush post-step budget не является атомарной предварительной резервацией.

Предлагаемые коды M9 (не утверждение о текущем enum): `NOT_AVAILABLE`, `PERMISSION_DENIED`, `QUOTA_EXCEEDED`, `INVALID_ARGUMENT`, `BUSY`, `TIMEOUT`, `CLOSED`, `NETWORK`, `PROVIDER_ERROR`. Не заявлять полной очистки ошибок: гарантия всех путей — **не найдено**; цель — исключить ключи, заголовки, пути, сырой вывод и детали, раскрывающие запрещённую роль.

## 7. Приёмка и ограничения доказательств

Все тесты ниже — **будущие, пока не существующие**. Использовать bounded waits по virtual clock/barrier, детерминированный fake adapter, не облако, и независимый observable oracle. Fake alone не доказывает OS-изоляцию. Где тест проверяет блокировку, положительный sentinel/control должен доказать достижимость fixture, а sink — увидеть намеренную разрешённую инъекцию. Все тесты без эффектов вне scratch; cleanup в finally и проверка очистки при следующем старте.

| Будущий тест | Явное воздействие/мутация | Независимый observable oracle |
|---|---|---|
| `roles_return_only_permitted_available_roles` | Удалить фильтр manifest/consent. | Результат содержит только разрешённую; adapter фиксирует контрольную и отсутствие запрещённой; запрещённость не подтверждает глобальное существование. |
| `chat_rejects_forbidden_messages_and_provider_knobs` | Разрешить system/tool и поля endpoint/header/key. | Запрос отвергнут до start; boundary observer видит разрешённый контроль и не видит запрещённые поля. |
| `credential_sentinel_never_crosses_the_rush_boundary` | Пробросить сырые provider errors/headers или credentials в ответ. | Проверяющий границу подтверждает контрольный путь и отсутствие секретного sentinel в API, логах, событиях, args процесса и сети. Не является OS-доказательством. |
| `provider_observer_rejects_endpoint_and_redirect_injection` | Принять endpoint/redirect/recipient от приложения. | Независимый destination observer видит только собственный разрешённый адрес и блокирует перенаправление; sink подтверждает контроль. |
| `same_app_id_with_different_signer_or_digest_isolated` | Ключевать по публичному app ID вместо authority. | Независимое хранилище authority показывает раздельную identity/квоту по заданным правилам подписанного и неподписанного пакетов. |
| `tool_consent_change_and_journal_gate_are_enforced` | Не перепроверять хеш схемы или запускать handler до записи журнала. | Согласие требуется заново; недоступный журнал оставляет эффект нулевым; контрольный handler и journal sink наблюдаемы. |
| `tool_call_dispatch_and_result_are_single_use` | Убрать атомарное потребление pending tuple или привязку сессии. | Независимый handler counter видит ровно один control effect; dispatch не зависит от iterator, replay/чужая сессия не создают эффект. |
| `rush_session_has_no_builtin_or_personal_authority` | Переиспользовать личную сессию или разрешить встроенный инструмент. | Adapter/session observer видит scoped пустую сессию и контрольное открытие; ни личная authority, ни инструменты не переданы. |
| `per_app_quota_and_journal_do_not_cross_packages` | Разделить проверку и резерв квоты либо убрать authority-фильтр журнала. | Независимые устойчивые счётчики не превышают лимит и записи не смешиваются; запись видна пользователю в журнале нужной authority, не странице. |
| `credit_deadlines_cancel_and_terminal_events_are_bounded` | Убрать лимит буфера/дедлайн или проверку закрытой сессии перед публикацией. | Virtual clock и bounded buffer observer показывают дедлайн/кредит, одну ошибку `CLOSED` или успех `end(completed)`, ноль событий после исхода и успешный контрольный stream. |

Отдельная adversarial-проверка OS на Windows, macOS и Linux должна попытаться прочитать env/config/data из дочернего процесса, обойти пути/symlink, запустить sidecar/shell, осмотреть соседний процесс, отправить сетью секрет и прочитать чужой журнал. Зафиксировать механизм и пределы; fake adapter, unit-тест и скрин согласия изоляцию не доказывают. Неподдерживаемая граница означает отказ в запуске на этой платформе.

## 8. Объём и открытые вопросы

M9.1 включает этот проектный документ и одну ссылку в плане этапов. Реализация, тесты и зависимости не добавляются; результаты CI не заявляются. Будущий выбор и реализация транспорта вынесены в отдельную задачу #167.

Полный UI вне CLI не входит в M9. Не цели: выбор транспорта в рамках этой спецификации, изменение хранения credentials Rush, общий provider SDK, произвольные model IDs, личная история, широкий Web API, автономные инструменты, OS-изоляция в этом изменении. Открытыми остаются конкретный аутентифицированный адаптер, OS-механизмы и принципал, сроки хранения журнала, гарантии usage провайдеров и отображение протокольной отмены/credit.

Проверка этого изменения документационная: тесты, сборки, CI и обращения к провайдерам не запускались и не заявляются.
